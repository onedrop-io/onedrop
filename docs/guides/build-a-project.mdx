## Start a project

After logging in you see **"what are we working on today?"** and three ways to start:

- **Start from scratch**: type a description of the app you want and press Enter.
- **Or start from a template**: pick a ready-made business app, change anything, then send it.
- **Or install a free app**: pick a popular open-source app, and OneDrop sets it up for you.

As you type, OneDrop checks whether a template or free app already does what you describe. If one does, up to three show under the message box as **This might already exist**. Click one to start from it (what you typed is kept after its description), click **No thanks** to hide them, or just send yours to start from scratch.

OneDrop then:

1. Creates a project named after your description (or the template)
2. Starts a sandbox for it (the preview shows "Starting sandbox…")
3. Sends your description to the agent

You land in the project's workspace: chat on the left, preview on the right.

<Tip>
    The same three ways to start are on your install's home page. Pick one there before you have an account, and it stays beside the sign-up form (with **Not now** to drop it), then waits on the new-project page once you've signed up and connected an AI.
</Tip>

### Start from a template

Under the message box are templates for apps teams usually keep in spreadsheets: **Sales CRM**, **Project Tracker**, **Content Calendar**, **Inventory**, **Hiring Pipeline**, **Event Planner**, **Help Desk**, **Time-Off Tracker**, **Expense Approvals**, **Product Roadmap**, **Bug Tracker**, **Goals & OKRs**, **Customer Feedback**, **Team Directory**, **Employee Onboarding**, **Equipment Checkout**, **Shift Schedule**, **Client Portal**, **Grant Tracker**, **Volunteer Scheduling**, and **Rental Properties**.

Picking one fills the message box with a full description: the records the app keeps, the views it shows (tables, boards, calendars, public forms), who signs in, and sample data to try it with. Change anything you like before sending, such as "for our three warehouses" or "add a field for the lead source". The project is named after the template; rename it from the sidebar any time.

### Install a free app

Below the templates, under **Or install a free app**, are about 500 open-source apps, ready to run, with the popular ones first (Twenty CRM, Chatwoot, n8n, Cal.com, Plausible, NocoDB, Documenso, Plane, Metabase…). The popular ones also turn in a coverflow at the top: click one at the side to bring it forward, or the one in the middle to see its details. It pauses while your pointer is over it, and stays still if your system is set to reduce motion. They come from template registries, starting with [Dokploy's](https://templates.dokploy.com). Type in the search box (or press <kbd>⌘</kbd> <kbd>K</kbd>, <kbd>Ctrl</kbd> <kbd>K</kbd> on Windows and Linux, from anywhere on the page to jump to it) to find one by name, description or tag (such as `analytics` or `cms`), or pick a category (Monitoring, Database, AI…). Click an app (or press Enter to open the first match) to see what it is: pictures of it (its website's preview image, then screenshots from the Umbrel and CasaOS app stores when they list it; use the arrows or the arrow keys to step through), its description, version, categories, links to its website, source code and docs, and what happens when you use it. Click **Use** to start the project from it straight away; ask for any changes in the chat once it's running.

A registry template is a Docker Compose stack. Using one starts the project with "Set up …" as the first message. When the project starts, OneDrop puts the template's `docker-compose.yml` in the project and its registry settings in `.onedrop/template.toml`. The agent then writes the `.env` (with new random passwords and secrets), sets the stack up as the preview, gets it running, and tells you how to sign in. The stack's containers show in the [Services tab](/guides/workspace#services).

<Info>
Registry templates need Docker inside sandboxes, which an admin turns on in **Settings → Sandboxes → Docker** (see [Run a project's Docker Compose](/guides/docker-compose)). Until then they're greyed out; if you're an admin, the note under them links straight to that page.
</Info>

If a registry can't be reached, the built-in templates still work and the registry's are tried again a few minutes later. If a template's files can't be downloaded when the project starts, the chat says so and the agent doesn't start.

#### Add a registry

The pictures are set in `config/sandbox.php` under `app_screenshots`: turn off website previews with `SANDBOX_APP_SCREENSHOTS_WEBSITE_PREVIEWS=false`, or an app store with `SANDBOX_APP_SCREENSHOTS_UMBREL=false` / `SANDBOX_APP_SCREENSHOTS_CASAOS=false`. Any app store whose screenshots are in a GitHub repository can be added there.

Registries are listed in `config/sandbox.php` under `template_registries`. Each has a `name`, a `format`, a `url` and the `popular` template ids shown under the prompt; any registry laid out like Dokploy's (a `meta.json` index and a `blueprints/<id>/` folder per template), such as your own fork, works with `'format' => 'dokploy'`. Point the Dokploy entry somewhere else with `SANDBOX_TEMPLATES_DOKPLOY_URL`, or set it to an empty value to turn it off. Each registry's list is cached for a day.

### Start from a repository

To work on an app you already have, click **Repository** next to the agent picker under the message box. A repository field opens above the message box (the templates hide while it's open). Enter any of these:

- `owner/name`, for a GitHub repository
- A GitHub link, such as `https://github.com/acme/website`. A link to a branch (`…/tree/redesign`) imports that branch instead of the default one.
- Any HTTPS git URL, such as a GitLab or Forgejo repository anyone can read

The message box becomes optional: say what you want done, like "add dark mode", or leave it empty and the agent gets the app running in the preview. Press Enter to start.

OneDrop checks it can reach the repository first, and tells you if it can't. It then creates a project named after the repository, brings the branch into the project's sandbox, connects the repository in [Tools → Git](/guides/git) so you can pull and push later, and starts the agent.

<Note>
    Private repositories need GitHub connected. If your OneDrop has the GitHub
    App set up, click **Connect GitHub** under the repository field, choose
    which repositories OneDrop can reach, and you come back with your
    repositories listed as you type. Public repositories work without connecting
    anything; to push to one later, connect it with a token in Tools → Git.
</Note>

### What your app is built with

Unless you ask for something else, the agent builds every app on [Laravel](https://laravel.com) with React. Even a simple app starts with sign-in, a database, background jobs, live updates, and file storage in place, so when you later ask for accounts, email, uploads, or "show new orders without refreshing", the agent adds them to the app you have instead of rebuilding it.

Asking for React, Tailwind, a website, or a landing page still gets this setup, since it already uses React and Tailwind. If you want a different framework, name it in your first message, for example "use Next.js" or "a static site with no server".

## Watch the agent work

The chat updates on its own while the agent works:

- **Thinking…** appears as soon as you send a message
- Short grey lines show each step, such as "Creating src/App.tsx" or "Running Install dependencies"
- The agent's replies appear as it writes them, formatted with headings, lists, links, tables, and syntax-highlighted code blocks (links open in a new tab)

When the agent sets up the app's dev server, the preview switches from the placeholder to your app. It updates while the agent works: apps with hot reload (Vite, Next.js) update in place, and Laravel apps reload each time a rebuild changes their assets or a PHP file changes. It reloads once more when the agent finishes. To copy the preview's address, hover it and click the copy button.

## Keep going

Send follow-up messages to change the app, for example "make the Start button blue" or "add a page for reports". The agent remembers the whole conversation for that project.

<Tip>
    Press **Up** in an empty message box to bring back your last prompt, and
    keep pressing it to go further back. **Down** steps forward again.
</Tip>

Messages you send while the agent is working are queued and run when it finishes. Press ⌘/Ctrl+Enter to stop the current run and send yours right away, or ⌥/Alt+Enter to always queue it.

When OpenRouter is set up (your connection or the platform's key), [Jev](https://openrouter.ai/docs/guides/community/jev) also reads a message you send with Enter while the agent works. If it corrects or changes what the agent is doing ("actually, put the form on the About page"), it's sent right away instead of waiting, and the chat says "Sent now: it changes what the agent is doing". A separate request still waits its turn.

### Before a message is sent

Jev checks each message you send in the chat once, in well under a second:

- **A pasted secret.** If the message contains an API key, password, token or a database URL with a password, it isn't sent yet. The box above the message asks **This looks like a secret. Save it in Secrets instead?**, with a suggested name such as `STRIPE_SECRET_KEY`. **Save in Secrets** adds it to [Tools → Secrets](/guides/secrets) and sends your message with `(saved as STRIPE_SECRET_KEY in Secrets)` in its place; **Send anyway** sends it as typed.
- **A change to an earlier decision.** With [requirements](/guides/requirements) on, a message that would undo a decision the app recorded asks **This changes an earlier decision: … Go ahead?** **Go ahead** sends it and tells the agent the change is on purpose, so it rewrites the decision; **Cancel** leaves your message in the box to edit.

Your message stays in the box until it's sent. Without OpenRouter, or if Jev doesn't answer within a few seconds, messages are sent straight away as usual.

### Your code is saved after every turn

When the agent finishes or you stop it, OneDrop commits everything in the project to git, with your message as the commit message, and backs up the project's history outside its sandbox. Projects without a git repository get one on branch `main`; a project that already has one keeps its branches and history. Dependencies (`node_modules`, `vendor`), caches and `.env` secrets are never committed. If a project's sandbox is ever replaced without its files, the code comes back from the backup. See the history, go back to an earlier version, or push to GitHub in [Tools → Git](/guides/git).

## Attach images and files

Paste an image straight into the message box, drag files onto it, or click the paperclip. You can attach up to 10 files (10 MB each) to a message, with or without text, including when you start a new project. Thumbnails show above the box; click the **×** on one to remove it before sending.

The agent looks at attached images along with your text, so you can:

- **Show it what you mean.** Paste a screenshot, mockup, or sketch and say "build this" or "make the sidebar look like this".
- **Put it in your app.** Paste a logo and say "use this as the logo in the header". The agent copies it to the right place: next to the app's code for fixed parts of the design (logos, icons, backgrounds), or into [App Storage](/guides/app-storage) for content the app's users see and manage, such as sample photos in a gallery.

Other files (text, CSV, PDFs and so on) are handed to the agent as files it can open and use.

<Note>
    If the model you picked can't read images, OneDrop uses one from the same
    provider that can for that message, and the chat says which. If none can,
    the agent works from your text but still has the files.
</Note>

Attachments stay in the chat, and only people who can see the project can open them. If you stop the agent while messages are queued, their text comes back into the box but their attachments are removed, so attach them again.

## Draw on the preview

To show the agent what to change in your app's UI, click **Annotate** (the brush) in the Preview's header. The preview freezes as a picture of what's on screen: the page as you scrolled it, with any open menus and typed input.

<Steps>
    <Step title="Mark it up">
        Click where you want a note and type it (**Text** is picked to start with), or pick **Pen**, **Box** or **Arrow**. Marks come in red, yellow or blue. Each mark gets a number. To move a mark, drag it by its line, its text or its number. Undo with the arrow button (or ⌘/Ctrl+Z), clear them all with the bin (undo brings them back), or press **Cancel** (Esc) to go back to the preview.
    </Step>
    <Step title="Add it to the chat">
        Click **Add to chat**. The marked-up picture is attached to the message box, and the chat opens if it was hidden. When you send it, the agent is also told which element each numbered mark points at (for example `1. Box (red) around button#save.btn ("Save changes")`), so it can find the right code. That part isn't shown in the chat.
    </Step>
    <Step title="Say what to change">
        Type your request ("make 1 bigger and move it next to 2") and send it. If your notes on the picture already say it all, you can send the picture on its own.
    </Step>
</Steps>

<Note>
    If the page in the preview can't take its own picture, OneDrop says so and
    offers **Share the tab instead**. Your browser asks which tab to share; pick
    this one, and OneDrop takes the picture from there.
</Note>

## Inspect and rearrange the preview

To point at exact parts of your app, or try a different layout, click **Inspect** (the pointer in a square) in the Preview's header. The preview stays live, but clicks go to the inspector instead of your app:

- **Hover** to highlight an element. Its label shows how to find it (like `#save` or `nav > button`) and, for React or Vue apps in development, the component that draws it.
- **Click** to pick an element. Each pick gets a number and shows in a list over the preview, where you can type a note ("make this green"), pick its parent instead (the arrow), or remove it.
- **Drag** an element onto another. Drop it near either end of the other element to move it before or after; drop it in the middle to swap the two. The page shows the result straight away, only in your browser, and the move is listed with a number like a pick.

Click **Add to chat** to attach a picture of the page as it looks, with the picks and moves outlined and numbered, then say what you want and send it. The agent is told what each number is (the element, its component and source file when known, your note, and where you moved it), so it can make the change in the code. Removing a move from the list, **Cancel**, Esc, or clicking **Inspect** again puts the page back.



Your projects are listed in the sidebar: pinned ones under **Pinned**, the first 10 others under **Recent**, and archived ones under **Archived** (click it to expand). Only you (and admins) can see your projects.

### Sort your projects

Click the sort button (↑↓) next to **Recent** to choose how pinned and recent projects are ordered:

| Sort             | Order                                                                              |
| ---------------- | ---------------------------------------------------------------------------------- |
| **Last updated** | The default. Projects you worked on most recently come first.                      |
| **Created**      | Newest projects first.                                                             |
| **Manual**       | The order you dragged them into. New projects show at the top until you move them. |

To put a project where you want it, drag it up or down within **Pinned** or **Recent**. Dropping it switches the sort to **Manual**, and **Recent** becomes **Projects**. Press Escape while dragging to put it back. Your sort and order are saved to your account, so they follow you to other devices.

Click **Search** near the top of the sidebar to find any of your projects by name, archived ones included. Use the arrow keys and Enter to open one. **New project**, just above it, starts a new project.

A blue dot and bold name mean the agent is done and waiting for you: it replied in the project's main chat, or in one of its [tasks](/guides/tasks), since you last opened that chat. Tasks get their own dot too, so you can see which one finished. Replies that arrive while you're in another tab or app stay unread until you come back.

When OpenRouter is set up (your connection or the platform's key), [Jev](https://openrouter.ai/docs/guides/community/jev), a small decision model, reads the end of each turn's reply and tells done apart from waiting for you. A chat whose agent is waiting shows why under its name, in amber, until you send the next message:

| Label                        | The agent…                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------- |
| **Needs your answer**        | Asked you a question it needs answered to go on                              |
| **Needs something from you** | Needs a secret or key, a sign-in, a payment, or a decision only you can make |
| **Stuck**                    | Couldn't finish: it hit an error it couldn't fix, or gave up                 |

The label shows on the project, on each task in the sidebar, on **Main** in an opened project, and on the task's card on the [board](/guides/tasks#the-board). A finished turn has no label. Without Jev, there are no labels.

Each project has a tile showing its [app icon](/guides/app-icon), or its first letter until it has one. The badge on the tile's corner shows what the project is doing:

| Badge         | Meaning                                                                                                                |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Pulsing amber | The agent is working. What it's doing shows under the name in plain words, such as "Building the orders page" or "Testing the app", and updates as it goes. The chat shows each step in detail. |
| Green         | The app is [published](/guides/publish).                                                                               |
| Red           | The sandbox failed. "Sandbox failed" shows under the name; open the project to see the error.                          |

When you collapse the sidebar, your pinned and recent projects stay as tiles with their badges. Hover a tile to see the project's name.

### Project menu

Hover a project in the sidebar and click **⋮** for its menu. While the menu is open, you can also press the letter next to an action.

| Action                                | Key | What it does                                                                                                                                                                                                                        |
| ------------------------------------- | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Pin** / **Unpin**                   | `P` | Keeps the project at the top of the sidebar under **Pinned**.                                                                                                                                                                       |
| **Mark as unread** / **Mark as read** | `U` | Brings the unread dot back, as a reminder to come back to it. Doing this on the project you have open takes you to the new-project page, since opening the project marks it read again. Marking as read clears its tasks' dots too. |
| **Rename**                            | `R` | Changes the project's name. Renaming, regenerating the title, pinning, and marking don't move it in **Recent**.                                                                                                                     |
| **Regenerate title**                  |     | Has the project's AI read the chat and come up with a short title. A spinner shows next to the project until it's ready. The sandbox must be running; if the AI can't be asked, the name stays as it was.                           |
| **Share**                             |     | Shows your published app's link so you can copy it. If the app isn't published yet, [publish it](/guides/publish) first.                                                                                                            |
| **Copy link**                         | `C` | Copies the link to the project's workspace. Only you and admins can open it.                                                                                                                                                        |
| **Archive** / **Unarchive**           | `A` | Moves the project out of **Pinned** and **Recent** into **Archived**. Nothing is deleted, and the app stays published.                                                                                                              |
| **Delete**                            | `D` | After you confirm, takes the app offline and permanently deletes the chat, attachments, and the sandbox with all its files. This can't be undone. Any tab still open on it moves to the new-project page.                                                                                   |
