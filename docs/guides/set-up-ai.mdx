---
title: 'Set up your AI'
description: 'Connect Anthropic, OpenAI, Google Gemini, OpenRouter, or Ollama so the agent can build with your own account.'
---

The agent that builds your apps uses your own AI account: your Claude or ChatGPT plan, or your own API key. You pay your provider directly, with no credits and no markup. You connect a provider after signing up (or, where the install offers them, [start on AI credits](#build-on-ai-credits)), and you can change it later in **Settings → AI**.

## Build on AI credits

On installs with AI credits turned on, you don't have to connect anything to start: the agent builds on **AI credits**, the platform's own AI (DeepSeek Flash, through OpenRouter). Each organization gets $5 of credits once, plus $1 every month. The monthly $1 is used first and doesn't carry over; the $5 never expires.

Credits pay for the AI at the provider's price, with no markup. A small change costs a few cents. While a project builds on credits, what's left shows beside the model picker under the chat box: it turns amber below $0.50 and red once it's used up. Hover it to see this month's part and the welcome part. The **Usage** page shows the same at the top, with when the next $1 arrives.

When the credits run out, the chat says when the next $1 arrives. To keep building now, connect your own AI in **Settings → AI**. Once you have, **AI credits** stays in the model picker as one more choice.

<Note>
  While AI credits are on, each person can own one organization. You can still join as many as you're invited to.
</Note>

## After signing up

OneDrop asks **Which AI do you use?** and shows five icons: Claude, Codex, OpenRouter, Gemini and Ollama. Click the one you have an account with, and OneDrop shows only that provider's setup, starting with your subscription (or sign-in). If you'd rather use an API key, click the small **…instead** link under it. Click **Choose a different AI** to go back to the icons. Once you've connected one, OneDrop takes you to the new-project prompt.

## Providers

<Tabs>
  <Tab title="Claude (Anthropic)">
    To build on your Claude Pro or Max plan, click **Use my Claude subscription**. There's nothing to paste: you sign in to Claude from your project, in Claude Code's own sign-in.

    <Steps>
      <Step title="Open a project on Claude Code">
        A subscription only works with the [Claude Code agent](#choose-the-agent). Anthropic lets its own agent use a subscription, but not other agents like OpenCode.
      </Step>
      <Step title="Sign in to Claude">
        Above the chat box, click **Sign in to Claude**. A new **Shell** tab opens and runs `claude auth login` (on a phone, the page switches to **Workspace** to show it).
      </Step>
      <Step title="Approve on Claude">
        Open the link it shows, sign in to Claude and approve. Copy the code Claude gives you and paste it into the Shell tab.
      </Step>
      <Step title="Start building">
        Once the Shell says **Login successful**, the workspace switches back to the **Preview** tab (on a phone, the page switches back to **Chat**) and the line above the chat box says who Claude Code is signed in as. Send your message.
      </Step>
    </Steps>

    <Note>
      OneDrop never sees or stores your Claude login: it stays inside Claude Code, in your sandboxes, as Anthropic requires. On OneDrop installs that use Docker sandboxes, one sign-in works in all of your projects. On other sandbox providers, sign in once in each project.
    </Note>

    If Claude turns down your sign-in, the chat tries your message once more by itself. If Claude Code isn't signed in, or your sign-in has really expired, the chat tells you to sign in again and **Sign in to Claude** comes back above the chat box. Once you've signed in, the chat picks your message back up by itself (even if you reloaded the page meanwhile), so you don't need to send it again. Disconnecting Claude in **Settings → AI** signs Claude Code out of your sandboxes. Claude subscription tokens from `claude setup-token` can't be pasted.

    To pay per use instead, click **Use an Anthropic API key instead** and paste a key from [console.anthropic.com](https://console.anthropic.com/settings/keys). OneDrop checks the key with Anthropic before saving it.

  </Tab>
  <Tab title="OpenAI">
    Sign in with your ChatGPT account to use your ChatGPT Plus or Pro plan instead of paying for API usage:

    <Steps>
      <Step title="Start sign-in">
        On the Codex card, click **Sign in with ChatGPT**. OneDrop shows a one-time code.
      </Step>
      <Step title="Approve on OpenAI">
        Open [auth.openai.com/codex/device](https://auth.openai.com/codex/device), sign in to ChatGPT, and enter the code. The code expires after 15 minutes.
      </Step>
      <Step title="Wait for OneDrop">
        Keep the OneDrop tab open. It connects Codex as soon as you approve.
      </Step>
    </Steps>

    If OpenAI says to enable device code sign-in, turn it on in ChatGPT under **Settings → Security**, then click **Get a new code** in OneDrop. A code issued before you changed the setting keeps failing. On a ChatGPT Business or Enterprise workspace, an admin may need to allow device code sign-in first.

    Your Codex connection works with two agents: OpenCode (pick an OpenAI model) or OpenAI's own [Codex agent](#choose-the-agent).

    OneDrop keeps your ChatGPT sign-in and refreshes it for you. Sandboxes only get a short-lived access token, never the refresh token. If OpenAI ends the sign-in (for example, after you sign out of all devices), the chat asks you to sign in with ChatGPT again.

    <Note>
      On a ChatGPT plan, the agent can only use the models OpenAI includes with Codex (currently recent GPT models, such as `gpt-5.5`). The model picker only lists those, and projects start on the first one if the default OpenAI model isn't included.
    </Note>

    To pay per use instead, click **Paste an OpenAI API key instead** and paste a key from [platform.openai.com](https://platform.openai.com/api-keys). OneDrop checks it with OpenAI before saving it.

  </Tab>
  <Tab title="Gemini (Google)">
    Paste a Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey). OneDrop checks the key with Google before saving it. Usage is billed to your AI Studio account, which has a free tier.

    <Note>
      You can't connect a Gemini subscription (Google AI Pro or Ultra). Google's terms forbid other apps from using the Gemini CLI sign-in, and Google suspends accounts that do. Use an API key, or pick a Gemini model through OpenRouter.
    </Note>

  </Tab>
  <Tab title="Ollama">
    Paste an Ollama API key from [ollama.com/settings/keys](https://ollama.com/settings/keys). OneDrop checks the key with Ollama before saving it. The agent runs open models such as GLM, Kimi, DeepSeek and Qwen on Ollama Cloud, billed to your Ollama account (which has a free plan). Ollama models run on the OpenCode agent.

    ### Your own Ollama server

    To use models you run yourself, click **Use my own Ollama server instead**:

    <Steps>
      <Step title="Enter the server's URL">
        For example `https://ollama.example.com`. Don't add `/v1` or `/api`.
      </Step>
      <Step title="Add a key, if it needs one">
        If your server sits behind a reverse proxy that checks a token, paste it. OneDrop sends it as `Authorization: Bearer <key>`. Leave it empty for a server without one.
      </Step>
      <Step title="Connect">
        OneDrop checks that the server answers at `/api/tags` and lists its models. The model picker then shows every model you've pulled on it, at no cost.
      </Step>
    </Steps>

    <Warning>
      Your sandboxes run on a server, so your Ollama server needs a public address. OneDrop refuses private, loopback and internal addresses (like `localhost` or `192.168.x.x`). Put it behind a reverse proxy with a key, and don't expose an Ollama server without one.
    </Warning>

    <Note>
      On a local install (`APP_ENV=local`), private addresses are allowed. In Docker sandboxes, `http://localhost:11434` is your own machine. Self-hosters can allow private addresses on a server with `SANDBOX_OLLAMA_PRIVATE_SERVERS=true`.
    </Note>

    ### Run OneDrop's checks on your server

    OneDrop runs small checks around the agent: how a turn ended, whether a message holds a secret, which preview errors are real, how big a request is for **Auto**. They normally use Jev on OpenRouter. If you pull [Nimble](https://ollama.com/library/nimble) on your server, OneDrop asks it there instead, so those checks are free and stay on your server:

    ```bash
    ollama pull nimble
    ```

    OneDrop sees Nimble within an hour (it rereads your server's model list hourly). Nimble needs Ollama 0.35 or later. If Nimble fails, that check is skipped. OneDrop doesn't send it to OpenRouter instead.

  </Tab>
  <Tab title="OpenRouter">
    Click **Sign in with OpenRouter** and approve access. OpenRouter creates a key you control and can revoke. A small link lets you paste an existing OpenRouter key instead.
  </Tab>

## Manage connections

In **Settings → AI** you can:

- See each connected provider, showing only the last four characters of its key (or of your ChatGPT account ID)
- Reconnect with a new key
- Choose which provider is the default when you have more than one
- Disconnect a provider

Keys are encrypted in the database, never sent back to your browser, and only passed to the agent inside your project sandboxes.

## Choose the agent

Each project runs one of three agents in its sandbox. The agent picker sits under the chat box, left of the model picker, in both the new-project prompt and the project chat.

| Agent           | Runs                                                                      | Best for                                          |
| --------------- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| **OpenCode**    | Any connected provider except a Claude subscription                       | Choosing between providers and hundreds of models |
| **Claude Code** | Claude models only, with an Anthropic API key or your Claude subscription | Building on your Claude Pro or Max plan           |
| **Codex**       | OpenAI models only, with your ChatGPT sign-in or an OpenAI API key        | OpenAI's own agent, on your ChatGPT plan          |

- New projects start on whatever agent and model you picked last. Until you pick one, they start on your AI subscription: Claude Code for a Claude subscription, or OpenCode with Codex for a ChatGPT sign-in. Without a subscription, they start on OpenCode (or Claude Code, if that's the only agent your connections can run).
- Claude Code only shows up once you've connected Claude. While it's chosen, the model picker only lists Claude models.
- Codex only shows up once you've connected Codex. While it's chosen, the model picker only lists OpenAI models (on a ChatGPT plan, the ones OpenAI includes with Codex).
- Switching agents starts a fresh conversation: the new agent can't read the old one's history, but your app's files stay as they are. The chat notes the switch.
- You can't switch while the agent is working. Stop it or wait for it to finish first.

## Choose a model

Each project runs on the model you pick. The picker sits under the chat box, in both the new-project prompt and the project chat.

- **Providers:** the rail on the left shows the providers you've connected. The star tab shows your favorites.
- **Search:** type to filter by name. Featured models are listed first; every other model that can use tools is under **More models**. OpenRouter alone offers a few hundred.
- **Recent:** the models you picked last are listed first under each provider.
- **Favorites:** hover a model and click its star.
- **Reasoning:** the button next to the model sets how hard it thinks, from the levels that model supports (for example Low, Medium, High, Extra high, Max). **Default** uses the model's own default.

### Auto

In the project chat, **Auto** at the top of a provider's list lets OneDrop pick the model and reasoning level for each message, from that provider. When you send a message, [Jev](https://openrouter.ai/docs/guides/community/jev), a small decision model on OpenRouter, sizes the request, and the run uses:

| Request | Claude | OpenAI | OpenRouter | Gemini | Ollama |
| --- | --- | --- | --- | --- | --- |
| A typo or tiny tweak | Sonnet 5, Low | GPT-6 Luna, Low | Gemini 3.8 Flash, Low | Gemini 3.8 Flash, Low | GLM-5.3, Low |
| A small change | Sonnet 5, Medium | GPT-6 Sol, Medium | Claude Sonnet 5, Medium | Gemini 3.8 Flash, Medium | GLM-5.3, High |
| A new feature | Opus 5.5, High | GPT-6 Sol, High | Claude Opus 5.5, High | Gemini 3.1 Pro, High | GLM-5.3, High |
| A big redesign or hard bug | Opus 5.5, Extra high | GPT-6 Astra, Extra high | Claude Opus 5.5, Extra high | Gemini 3.1 Pro, High | GLM-5.3, Max |

The chat shows what Auto picked for each run, for example "Auto picked Claude Sonnet 5 with low reasoning, for a small change". Without OpenRouter set up (your connection or the platform's key), or when Jev doesn't answer in time, Auto uses the provider's default model. A model your connection can't run (for example one a ChatGPT plan doesn't include) falls back to the default too. Whoever runs OneDrop can change the table (`sandbox.auto_models`).

Changing the model takes effect on your next message; the agent keeps the conversation. Each model shows its context size and price per million tokens (input/output).

New projects start on the model you picked last. Until you pick one, they start on your subscription's (or else your default provider's) default model, set by whoever runs OneDrop (`SANDBOX_MODEL_*` in [Configuration](/self-hosting/configuration#agent)).

<Warning>
    OpenRouter reserves the maximum possible cost of each request before running
    it. If your OpenRouter balance is low, requests can be refused even though
    the final cost would be small. The chat tells you when this happens; add
    credits and try again.
</Warning>
