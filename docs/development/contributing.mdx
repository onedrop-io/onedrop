The rules for working on OneDrop live in `AGENTS.md` at the repo root, and apply to people and coding agents alike.

## For every feature

1. Add it to `SPEC.md` first, as "User should be able to…" acceptance criteria with an ID like `AUTH-001`
2. Write Pest unit or feature tests, tagged with the spec ID: `->group('AUTH-001')`
3. Add a Pest browser test for big features
4. Update these docs in `./docs`
5. For major features, add a manual test checklist under `docs/testing/` (a hidden tab, for things the fakes can't prove, like real agents and publishing)
6. Run the tests before calling it done

## Commands

| Task                      | Command                                                |
| ------------------------- | ------------------------------------------------------ |
| Run everything locally    | `composer run dev`                                     |
| Run the test suite        | `php artisan test`                                     |
| Run browser tests         | `npm run build && vendor/bin/pest tests/Browser`       |
| Run real-Docker tests     | `RUN_DOCKER_TESTS=1 vendor/bin/pest tests/Integration` |
| Format PHP                | `vendor/bin/pint --dirty`                              |
| Lint and format front end | `npx vp check --fix`                                   |
| Type-check front end      | `npm run types:check`                                  |
| Preview these docs        | `cd docs && npx mint dev`                              |

## When CI fails

If the `tests` workflow fails on `main` or on a pull request from a branch in this repo, the `ci fix` workflow opens an issue with the failure, labelled `ci-fix`, and assigns it to Copilot cloud agent. Copilot finds and fixes the cause, then opens a pull request into the branch that failed. Review it like any other pull request; nothing lands without a merge. You may need to approve the workflow runs on Copilot's pull requests before the tests run.

It needs Copilot cloud agent turned on for the repository, and a `COPILOT_TOKEN` repository secret: a fine-grained personal access token from someone with a Copilot plan, with read access to metadata and read and write access to actions, contents, issues and pull requests. Without it the workflow does nothing. It skips pull requests from forks, runs whose branch already has newer commits, and branches that already have an open `ci-fix` issue.

`.github/workflows/copilot-setup-steps.yml` installs PHP, Node, the app and Playwright's Chromium before Copilot starts, the same way CI does.
