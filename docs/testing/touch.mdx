The browser tests emulate an iPad, which can't hover, but not a real one: an iPad with a trackpad or keyboard, Safari's sticky hover after a tap, or the on-screen keyboard. Check these on a real tablet (and a phone where noted).

## Buttons that show on hover elsewhere (TOUCH-001)

1. Open a running project with changes and a task, on a tablet with no trackpad attached.

- [ ] **Source Control:** every file shows its open, discard (↶) and stage (+) buttons; **Changes** shows stage all and discard all; each commit in **History** shows its **⋯** menu. Discard asks first.
- [ ] **Files panel:** every file and folder shows its **⋯** menu.
- [ ] **Sidebar:** each project shows **+** (New task) and **⋯**, and its name stays readable beside them. A project with tasks has a small chevron badge on its icon that shows and hides them; tapping the icon elsewhere opens the project.
- [ ] **Board:** each task card shows its menu.
- [ ] **Tests:** each group shows **Run**, and a step shows **Take over**.
- [ ] **Preview:** **Copy address** is there. **Apps page:** **Pin** is there. **App Storage → Commands:** **Copy** is there.
- [ ] Icon buttons are easy to tap without hitting the one next to them.

## Panes and tabs by touch (TOUCH-001)

- [ ] Split the workspace, then **Move this tab to pane 2** from pane 1's split menu moves the tab showing; a Shell keeps its session.
- [ ] With more tabs than fit, opening Source Control from the header's **Commit** scrolls its tab into view; the tab bar scrolls with a swipe.
- [ ] The dividers between panes, and beside the chat and files panel, can be dragged with a finger.

2. Attach a trackpad (or use a laptop).

- [ ] The same buttons show on hover only, as before; on a laptop nothing changed.

## The tab bar on a phone (LAYOUT-007)

1. Open a running project on a real phone (iPhone Safari and Android Chrome).

- [ ] The tab bar sits along the bottom above the home indicator, with **Chat**, **Preview**, **Tools**, **Shell** and **More**; each switches in one tap, and the chat's draft and the preview survive switching.
- [ ] With the on-screen keyboard open in the chat or a Shell, the bar doesn't cover what you're typing.
- [ ] **Shell** opens a Shell and the keyboard can type into it; after opening **Shell 2** from **More**, Chat then Shell comes back to Shell 2.
- [ ] **More** shows a count of other open tabs; opening Console from it shows **Console** in More's place; closing a tab there works.
- [ ] While the agent works, a dot pulses on **Chat** when the workspace is showing.
- [ ] The header shows only the sidebar button, the project's name, **⋯** and **Publish**. With changed files, **⋯** has a dot, and **Commit…** in it shows the count. **Share** in it opens a sheet whose prompt box stays above the keyboard while you type.

## Not covered yet

Note what happens, so it can be fixed:

- Dragging a tab itself by touch (moving it from the split menu works).
- A tablet held upright: the sidebar and chat leave the workspace little room.
- Shortcuts with no on-screen way (⌘P, ⌘⏎ in Source Control, ↑/↓ through files) with the on-screen keyboard.
- Reasons shown only as tooltips (a disabled button's "wait for the agent").
