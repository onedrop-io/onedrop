The Pest suite fakes GitHub and the sandbox's git. These checks need a real GitHub repository, a real sandbox and a real agent.

Set up: a project connected to a GitHub repository you can push to (GitHub App or token) with a GitHub Actions workflow that runs tests, and two open pull requests: one from a branch in the repository whose tests fail, and one from a fork.

## Browse and read (GIT-013)

- [ ] **Tools → Pull requests** lists the open pull requests with their checks, review and comment count; **Closed** lists closed and merged ones; search filters by title, number, branch and author.
- [ ] A pull request's page shows its description and comments formatted, its commits, and its files with diffs matching GitHub's.
- [ ] **Checks** lists the workflow's jobs; clicking the failed one shows the end of its real log.
- [ ] Reloading the page keeps the pull request open (`pr=` in the address).
- [ ] With a pull request open on **Files changed**, switch to the **Preview** tab and back to **Tools**: the same pull request opens on **Files changed**.
- [ ] With a GitHub App missing **Checks** or **Actions** read, an admin sees it named in Source Control, and the section says which permission GitHub wants.

## The agent checks out branches and pull requests (GIT-021)

Set up also: a second branch with a commit Main doesn't have, and a tag.

- [ ] Import the repository as a new project: in the Shell, `git branch -a` lists every remote branch as `remotes/origin/…`, and `git tag` lists the tag.
- [ ] `git remote -v` shows the repository's HTTPS address with no token in it; `cat .git/config` has no token or signed address.
- [ ] Push a new branch from your computer, then in the Shell run `git fetch origin`: the branch arrives without a password prompt.
- [ ] Ask the agent to "check out the `<branch>` branch": it switches, the preview restarts on that branch, and Source Control's branch menu shows it.
- [ ] Ask the agent to "check out PR #N": it fetches `pull/N/head` (or uses `gh pr checkout`), and the preview runs the pull request's code. `gh pr list` in the Shell lists the open pull requests.
- [ ] With uncommitted changes, ask it to switch branches: it asks first instead of stashing or discarding.
- [ ] `git push origin HEAD` in the Shell fails (the token is read-only); the agent, asked to push, says to use Source Control.
- [ ] Disconnect the remote in Source Control: `git remote` is empty within moments, and `remotes/origin/…` branches are still there. Reconnect: `origin` comes back.
- [ ] A project connected to a private GitLab repository with a token: `origin` is there, `git fetch` is refused, and the agent asks you to Pull from Source Control; **Pull** brings in every branch.

## Check out as a task (GIT-014)

- [ ] **Check out as task** opens the task, which says "Checking out…", then "Checked out #N at …" within a minute or two even for a large app (Pixwel/platform); the agent doesn't start.
- [ ] The task's sandbox has only the pull request's code: no `node_modules` or database files from Main until `.onedrop/dev` makes them, and its preview comes up once the app has set itself up.
- [ ] The task's preview runs the pull request's code; the Shell shows `git branch --show-current` as the pull request's branch.
- [ ] A message sent while it's checking out waits and runs after.
- [ ] Ask the agent for a small change: when its turn ends, "Pushed to #N" appears and the commit is on GitHub.
- [ ] With **Push after each turn** off, the next turn isn't pushed; **Push** pushes it.
- [ ] Push a commit to the branch from your computer, then **Pull**: it's merged into the task's copy and the agent brings the copy up to date. **Pull** again says "Already up to date".
- [ ] Push from your computer, then **Push** in the task without pulling: it fails and says to pull first. Nothing is force-pushed.
- [ ] The fork's pull request checks out and runs; **Push** is disabled and says why.
- [ ] Main's preview and files are unchanged throughout.

## Fix failing checks (GIT-015)

- [ ] **Fix failing checks** on the failing pull request sends the failed job's name and log to its task's agent; it fixes the code, the fix is pushed, and the chat says "Checks passed on …" once the workflow passes.
- [ ] With **Fix failing checks automatically** on and a test that can't pass, the agent tries 3 times, then the chat says it stopped.
- [ ] The board's card shows the checks' state.

## Review comments (GIT-031)

Use a pull request on a repository with Copilot code review turned on, and the GitHub App subscribed to **Pull request review**. Ask Copilot to review a change that has an obvious typo and a missing doc update.

- [ ] The list shows the pull request's unresolved review comments count; its page lists Copilot's threads under **Conversation** with their code, waiting first.
- [ ] **Address N comments** checks it out (if needed) and the agent's prompt lists each thread as `T<number> · path:line`. When the turn ends, the fix is pushed and each thread shows the agent's draft reply marked Fixed, Declined or Needs you.
- [ ] Edit a draft and **Post reply**: the edited text shows on GitHub, from the OneDrop app, ending "Fixed in" and the commit, and the thread is resolved on GitHub. A declined reply posts without resolving.
- [ ] A Needs you reply shows in the task's chat and isn't posted by itself.
- [ ] **Apply suggestion** on a Copilot suggestion: the file changes in the task's copy, "Pushed to #N" appears, and the thread gets "Applied in …" and is resolved.
- [ ] Change those lines first, then **Apply suggestion**: it refuses and says to ask the agent.
- [ ] **Reply**, **Resolve** and **Unresolve** by hand work and show on GitHub, signed with your name.
- [ ] Set **Address review comments** to **From bots**, then ask Copilot for another review: within a minute or two the threads go to the task's agent by themselves. A person's comment on the same pull request doesn't go.
- [ ] Reply as an outsider (an account without push access) on a Copilot thread: that thread no longer goes by itself, but **Address comments** still sends it.
- [ ] With **Post the agent's replies without asking** on, the replies post and fixed threads resolve after the push, with no drafts left.
- [ ] Copilot reviewing each push (**Review new pushes** on): after 3 rounds the chat says it stopped addressing review comments automatically.
- [ ] A review on a pull request without a task, with the project set to **From bots**, checks it out and sends Copilot's threads; one from a fork doesn't.
- [ ] Unsubscribe the app from **Pull request review**: Source Control tells admins to subscribe it.

## The Pull requests page (GIT-022)

- [ ] The project's **⋮** menu has **Pull requests** under **Board** (**G** works with the menu open). Open the project from its menu: **Pull requests** is under **Board** in the sidebar too. A project without a GitHub repository lists it in neither.
- [ ] The page lists the same pull requests as Tools; open one, switch to **Files changed**, and reload: the same pull request and tab come back.
- [ ] **Check out as task** from the page goes to the new task, with the pull request beside its chat.

## Pull request tasks follow GitHub (GIT-023)

- [ ] Merge a checked-out pull request on GitHub, then open the board: within a minute (reload) its card is in **Done**, marked **Merged**, and its chat says "#N was merged on GitHub".
- [ ] Close another without merging: its task moves to Done, marked **Closed**.
- [ ] Drag the merged task back to Review and reload a few minutes later: it stays.
- [ ] On the merged task's page, **Push** and **Pull** are off, and a turn of its agent isn't pushed.
- [ ] A task's page shows **Changes** on its pull request bar, which opens the Changes tab against the pull request's base (GIT-030); its number opens the pull request's own **Files changed** in Tools.

## Open a pull request from a task (GIT-024)

- [ ] Start a task, let the agent change something, then click **Open pull request**: the bar says **Pushing to GitHub…**, then shows **Create on GitHub**, and the branch `onedrop/task-<id>-…` is on GitHub.
- [ ] **Create on GitHub** opens GitHub's compare page into the default branch (also when it isn't `main`), with a sensible AI-written title and description.
- [ ] Create the pull request: within two minutes, without reloading by hand more than once, the task shows the pull request's bar, its chat says "Opened #N", and it's in Review on the board. Its checks start being watched.
- [ ] Before creating it, ask the agent for another change and click **Push again**: the same branch gets the new commit.
- [ ] A project connected to GitLab doesn't offer **Open pull request**.

## Previews for every pull request (GIT-026, GIT-027, GIT-028)

Set up also: the GitHub App with its webhook on (`https://<install>/github/webhook`, Pull request events), `GITHUB_WEBHOOK_SECRET` set, and Deployments and Pull requests write permissions accepted on the installation. In the app's **Advanced → Recent deliveries**, deliveries should show `202`.

- [ ] Open a pull request from a branch: within a minute a task "#N …" appears on the board without anyone clicking, and its copy is made.
- [ ] On GitHub, the pull request shows **View deployment** (in progress, then active) and one OneDrop comment with **Open the preview**.
- [ ] Open the link in a private window, signed out of OneDrop: the app opens at `pr-<n>-<project>-<id>.<domain>`, and its pages, assets and API calls work. Opening the address without the key shows "Open this preview from its pull request".
- [ ] Push a commit to the branch from your computer: within a minute the comment says it's updating, the copy brings in the commit, a new deployment for that commit goes active, and the preview shows the change.
- [ ] Push while the task's agent is working: nothing is pulled until the agent finishes, then the next catch-up (open the Pull requests list) brings it in.
- [ ] **New link** on the task's bar: the old link's tab gets "Open this preview from its pull request" on its next request (within a minute on Cloudflare), and the comment and deployment have the new link.
- [ ] Merge the pull request: the deployment goes inactive, the comment says it was removed, and the task is in Done. A day later its copy is gone (or set `RemovePullRequestCopy::AFTER_HOURS` lower on a test install).
- [ ] Reopen a closed pull request within a day: the task leaves Done's "merged" state and the preview works again; after its copy was removed, a new copy is made.
- [ ] A pull request from a fork gets no task, deployment or comment until checked out by hand.
- [ ] Set **Preview** to **No pull requests**: new pull requests aren't checked out. Set it to **Every pull request**: open ones are checked out within moments.
- [ ] With an open pull request that has no task, set **Preview** to **New pull requests**: it isn't checked out, and the note says only new ones are. Open a new pull request: it's checked out within moments.
- [ ] With the webhook turned off on GitHub, a new pull request is still checked out within 5 minutes on a server (hourly on Laravel Cloud), or right away when the Pull requests list is opened.
- [ ] Remove the Deployments permission from the installation: the task's bar says GitHub refused, and the preview link still works.
- [ ] Sleeping copy: leave a preview unused for 20 minutes, then open its link: it wakes and loads.

## Hand-offs on AI credits (GIT-029)

Only on installs with AI credits on. Use a pull request task on Claude Code with a Claude subscription.

1. Sign Claude Code out in the task's Shell (`claude auth logout`).
2. Push a commit to the pull request on GitHub.

- [ ] The task brings in the commits; its chat says Claude isn't signed in, so this runs on AI credits (DeepSeek Flash).
- [ ] The hand-off runs on OpenCode (its steps show) and does what it was asked: installs, migrates, restarts, resolves any conflicts.
- [ ] The Usage page shows the run as paid by AI credits, and the credits balance goes down.
- [ ] After signing in again, a message you send runs on Claude Code and remembers the conversation from before the hand-off.
- [ ] A message you send while signed out still asks you to sign in, and doesn't run on credits.
- [ ] With **Fix failing checks automatically** on and a failing check, the fix also runs on AI credits while signed out.
